# 端末への保存と作例艦（v24）

## 保存先

アカウントに保存できないとき（`window.claude` の db が使えないとき）、設計はこの端末の IndexedDB に保存する。

- データベース `ks-yard`（版 1）に二つの保存領域を持つ。
  - `saves`：ユーザーが保存した設計（`id` で引く）
  - `examples`：同封の作例艦（`key` で引く）
- 以前は localStorage の `yard.saves` に、全設計を一つの JSON 配列として保存していた。保存のたびに配列全体を書き直し、下書きと同じ約 5 MB の上限を分け合っていた。
- 初めて開いたとき、`yard.saves` の設計を `saves` へ移し、`yard.saves` を消す。すでに同じ `id` がある設計は上書きしない。
- IndexedDB を開けない環境（一部のプライベートウィンドウなど）では、従来どおり localStorage に保存する。
- アカウントへの保存は変えない。

## 保存時の戦闘データ

設計を保存すると、その設計の戦闘データ（艦隊戦のプロファイルと、戦闘・操縦用の形状）を計算エンジンの背景キャッシュで作る（`prepareSavedCombat`）。

- 性能の計算が終わっていないうちに保存した設計は、「計算中」として保存する。計算が終わると、記録に艦種と全長を書き込み、そのとき戦闘データを作る（`completePendingSave`）。
- 計算が終わる前に設計を変えた場合、古い保存は完了させない。次の保存が改めて作る。

## 作例艦

作例艦の設計図（`data/examples/<key>/design.json.gz`）は、起動後に背景で取得する。取得が終わると、設計図と艦隊戦のプロファイル（`data/fleet.js` の行）を `examples` に入れる（`LocalExamples.seed`）。

- 同封の設計図が変わったとき（SHA-256 が変わったとき）だけ入れ直す。同封されなくなった作例は消す。
- 設計図の画面に「作例艦」の欄を加えた。この端末にある作例が全長の順に並ぶ。
  - **開く**：作例を開く（`openExample`）。
  - **複製して保存**：作例の設計を自分の設計として保存する。新しい `id` で保存し、戦闘データも作る。

## 画面側の処理の軽減

- 機関の外装（`engineSkinMesh`）を、外装を決める値ごとに使い回す（最大 384 件）。計算エンジンから設計の状態が届くたびに部品が新しいオブジェクトになり、以前は全機関の外装を作り直していた。
- 外装の頂点を写すとき、機関ごとに決まる値（元の機関、軸方向の倍率、向き）を先に一度だけ求める（`referenceEnginePointer`）。
- 参照形状の頂点法線（`indexedReference`）を、頂点配列ごとに一度だけ求める。

いずれも結果は変わらない（機関の外装の頂点は以前と同じ値になる）。

## 新規配置の部品一覧

新規配置の部品一覧が艦船用の武装の一覧（`WEAPONS`）だけを見ていたため、航空機用の武装（固定式レーザー砲、重レーザー砲、小型旋回砲塔、航空魚雷、爆弾など）が出ていなかった。旧来の武装の一覧と同じ `weaponKeys()` を使うようにした。
