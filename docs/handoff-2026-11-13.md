## 2. このブランチで直したもの（`claude/lucid-meitner-52bsni`）

### ユーザーの設計（2026-11-13 の報告）で見つかった不具合
設計の現物は `tests/fixtures/copied-structure-lost-parent-2026-11-13.json.gz`。

1. **複製・貼り付けした構造物が、親を失ったままになる**
   - 症状
     - 楕円体 102 と 103 が「追加元の構造物が見つかりません」（parent-missing）で拒否されていた。
     - 面取り 107 が赤枠になっていた（parent-required、接地していない）。
   - 原因
     - `remapPlacementCopy` は、コピーに含まれない親の ID を残さない（別の艦の ID にならないようにするため）。
     - そのため、船体に付いた構造物を複製・貼り付け・ミラー複製すると、`unresolvedParentId` だけが残り、親を失う。
     - それを付け直す処理が無かった。ユーザーが後で船体の上へ動かしたり寸法を変えたりしても、直らなかった。
     - ミラー複製（103）は、親が分からないため、接点の値が反転されないまま写されていた。
   - 修正：`placementAdoptContactParent`（`js/core.js`）
     - 親を失った構造物は、この艦の中で実際に接触している、または重なっている本体に付け直す（「重なりは接続」の決定）。主船体を優先し、次に接触面積の大きいものを選ぶ。
     - 位置・向き・形は変えない。保存された要求（`requestedGeometry`）は、現在の形に合わせる。エラー中の部品は、編集しても要求に反映されていなかったため。
     - 重なり（減り込み）は接触面が無いので、部品の中心を通る光線が親に当たる点を接点にする。
     - どこにも触れていなければ、未解決のまま残る。同じ状態では二度は測らない。
2. **「形状変更で面が失われました」が 142 件出る**
   - 原因
     - 削除した部品や、コピーで面が見つからなかった部品について、既定値のままの面の記録（`authored:false`）が残っていた。
     - その記録がすべて警告になっていた。表面パッチの上限（512）も使っていた。
   - 修正
     - 既定値のままで、面が無くなった記録は、読み込み時に捨てる。コピーもしない。
     - ユーザーが設定した記録（`authored:true`）は残し、今までどおり警告する。
     - 作例 28 隻には、該当する記録は無い。

     - プリセットの平面形を 5% 刻みで取り、直線で再現できる断面は省く。
     - 端の断面は、最小値の 0.02 にする（楔形と同じ）。
     - 容積はプリセットの ±1.2% 以内に入る。楔形と槍形は、今までどおり 2 断面のまま。
5. **削って切り離された構造物が、再読込すると赤枠になる**

     - 今は接触していない。
     - 削りが無ければ接触している。

## 6. 進め方の注意（前回から変わらない）

- **PR とマージ**
  - PR は main を基準にする（重ねない）。マージはユーザーが行う。force push はしない。
  - PR が複数たまって衝突しそうなときは、1 本にまとめる方法がある（#102 の前例）。
  - まとめる時の注意
    - `index.html` の衝突は、ハッシュの行だけを解決してから作り直す。ファイル全体を片側に寄せると、UI の変更が消える（#102 で一度起きた）。
- **検証**
  - 検証の出力は `/tmp/ks-verify/<日時>-<内容>/` に置く。基準資料は、意図した時だけ更新する。
  - 共用マシンのメモリは少ない。テストとブラウザは同時に動かさない。ブラウザは 1 つだけにする。
- **レビュー**
  - 担当は `regression-reviewer`、`physics-reviewer`、`reference-fidelity-reviewer`。判定は PASS、FAIL、UNVERIFIED の 3 つ。
  - `regression-reviewer` が追加の確認を求めたら、Opus / high で確認する。
