# リアクター出力を基準とする機関入力

機関の手入力の「入力定格」を、推進能力の上限として使う方式を廃止する。接続されたリアクターの有限な供給力を機関の入力基準とし、スロットルはその基準に対する出力要求を表す。実推力、噴射、発熱は共通の配電処理で実際に受け取った電力から計算する。

## 電力の分配

「推進優先」では、冷却・艦内維持に必須の電力を確保したうえで推進を優先する。全出力では残りの供給可能電力を機関へ回せる。既存の兵装優先・防御優先などの明示的な配分は保持し、スロットル操作で選択を無断変更しない。

複数機関が同じ炉を使う場合、供給予算は一度だけ共有する。機関の数を増やしても炉の電力を複製しない。同じ供給源に対する25%の出力要求を、機関の数だけ加算して100%相当へ増やさない。到達できない炉から電力を借りず、給電経路の損失・手動経路の容量・機械伝達路・ノズルの有効性を検証する。

機関の容積・等級に由来する旧入力上限、手入力した旧定格、旧上限を引き継いだ自動配電路の容量を、新方式の隠れた上限として残さない。内部に残る互換用のフィールド名だけで、旧入力定格が復活しないようにする。

## 変換、熱、構造

入力定格や密度超過を前提とした変換ペナルティは外し、既存の推進プロファイルの基準係数と変換効率を使う。基準の廃熱率5%を勝手な新係数へ置き換えない。実入力は有効な推進出力と実廃熱へ分かれ、配電損失は独立した熱として計上する。

機関本体・ノズル・伝達路の実形状、質量、設置判定を維持する。骨組み重量、縦強度による加速・推進入力制限、慣性制御、冷却・熱停止、燃料、損傷も保持する。これらに制限された場合、スロットル100%でも炉出力の全量を推進へ使えるとは限らない。

## 編集と互換

新規配置・編集から入力定格と入力密度上限の操作を除き、機関寸法、推進プロファイル、炉・機関・ノズルの接続を編集する。性能欄は接続炉による最大入力、実入力、実推力、変換効率、実廃熱を表示する。計算中に古い定格値を確定値として見せない。

旧図面の有限な定格・等級は、過去の購入費用と由来の互換情報として保持できるが、推進の入力上限へ使わない。既存機器の価格を炉出力へ自動連動させず、新規機関の通常価格は既存の機関容積と通常価格係数から求める。船体密度・機器価格係数の追加調整や一斉再設計は行わない。

保存・艦隊・艦載機のプロファイルは新しい入力モデルへ移行し、旧入力上限のキャッシュを再利用しない。新しい最大推力から、[TIE/ln100MGLT・ヴェネター級50MGLTを基準とする抵抗](force-balanced-sublight-speed.md)を校正する。校正基準の移行は一度だけ行い、運転中のスロットルや搭載重量の変更で基準を作り直さない。

旧保存だけではノズル寸法などの根拠が足りず、より大きな物理伝達容量を証明できない場合は、既知の有限上限を保持する。図面から再生成できる場合は実寸で再検証する。保存済みの部品形状・ID・機器設定を自動で縮小・拡大しない。

作例の新規生成では、旧「機関容積を増やして指定Gへ合わせる」自動調整を停止する。入力が炉出力で決まる新方式では、この旧調整で形状を動かさない。初期の作例形状、通常の設備配置・支持・冷却処理は使い、旧G目標へ到達したと報告しない。保存図面の読込に作例生成処理を適用しない。旧容積式に専用化された履歴上の監査プリセットは、現行方式の検収とは区別する。
