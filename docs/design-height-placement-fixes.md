# 設計操作・配置・迎撃の修正

基準は main `e21a5474373f4ce2e8d52d5f83f5e2ec8470c908`（PR #70）。
この追補の操作仕様は [設計操作の整理](design-ui-refinement.md)より後の追加指示を優先する。
骨組み重量・強度・縦強度の加速／推進入力制限と、機器の既存の係数は維持する。

## 高さと実形状

高さ40mの成形済み構造物を100mへ変更したとき、元形状と中心だけが更新され、
古い40mのローカルメッシュが新しい中心へ移動していた。
親の上面Y=10mの再現例では、本来Y=10〜100mとなる物体がY=40〜70mの板として表示された。
さらに、Workerの新しいメッシュが届いても、元入力や全体コンテキストが同じという理由で
プレビューが更新されない経路があった。

- Coreは実際の高さ変更時に旧有効メッシュと関連キャッシュを無効化する。
  設置側を固定して高さを変え、元形状と成形結果を区別する。
- Appの編集用モデルとGfxのプレビューは、入力の有効性と有効形状の置換・除去を確認する。
  同じ世代内のWorker更新でも古い形状を使い続けない。
- 変化のない部品のキャッシュを再利用し、カメラ操作で形状を再生成しない。
- 上下反転・垂直・面配置・初回計算前の編集・保存復元を検証する。
  旧 `legacy-fit` も、同じ親・面・元形状であれば高さ変更や再読込で埋込み位置を据え直さない。
  新しい面の指定や親の変更では通常の位置合わせを行う。

## 配置と編集

- 「連続配置」のチェックは初期OFF。通常は1回の配置で終了する。
  左右・上下対称やユーザー部品の一組も1回と扱う。チェック時だけ同じ設定で続けて置ける。
- 部品の情報窓へ「複製」を追加する。既存の複製コマンドで、子孫・安定IDの付替えと
  1回のUndoを共有する。外部の親をコピーに含めない場合の既存の再接続規則も保持する。
- 新規配置は上部へ「取消」と「設置」を並べ、下部の重複する操作欄を除く。
- 編集は「閉じる」で反映し、明示した「取消」で編集前へ戻す。
  変更は1回のUndo単位にまとめ、計算の完了を待って閉じる方式にはしない。
  別の部品・画面・外装／内装への移動でも編集を保持する。
- 内装は母体のドロップダウンが未指定でも配置を開始できる。
  その場合は3Dでタップした船体・構造物を、その配置の母体として使う。
  明示した母体は固定し、別の構造物へ無断で切り替えない。
  固定機器の実寸、切り取り・容積維持の検証は既存Coreのまま行う。

## 設置一覧からの一括削除

「設置一覧」の「種類ごとにまとめて削除」で、区画・設備の種類と実際の個数を確認して削除する。
部品定義と装備定義を使ってまとめ、手動グループ内や対称側の同種部品も対象に含める。
表示中の外装／内装の対象だけを列挙し、グループ化されていることを理由に別種類まで削除しない。

構造物は対象IDを一括で既存Coreへ渡し、接続を失う子の削除・別の支持への再接続を既存規則で処理する。
兵装はトレンチ砲群の元設定を含む既存の削除処理を使う。
1回の一括削除は1回のUndo単位とし、部品・親子参照・ハッチ・グループ等を復元できる。
一覧表示のために実形状を再計算せず、削除後の計算は既存のバックグラウンド処理へ渡す。

## 武装と諸元

兵装の種別・威力の小タブは、スワイプと左右ボタンで送るカルーセルにする。
端では送りボタンを無効化し、選択後もスクロール位置を保持する。
威力の分類は1発・1門あたりとし、40TTの単装・連装・多連装を40TTへまとめる。

武装の実形状プレビューへ、威力・旋回速度・射程・最大使用電力／秒・最大発熱／秒を表示する。
威力は1門あたり、電力と発熱は選択した武装全体の最大値であることを明記する。
実際の部品設定・既存Coreの戦闘とエネルギー計算を使い、給電元や弾薬に依存して
未確定な値は未確定と表示する。「武装の威力と出典」の重複UIは除き、出典データを保持する。

右側の諸元へ設備最大発熱／秒と排熱能力／秒を追加する。
前者は計算済みの各設備について負荷条件ごとの最大発熱を合計し、
後者は設置済み排熱設備と船体表面の定格容量を合計する。
定格容量は、熱種・給電・輸送経路に制約される実排熱量とは区別して説明する。
未計算の値をゼロで置き換えない。

## 船体へ埋め込んだ外装型タービン

外装と機関本体は移動時に一緒に追従していたが、機関の寸法を編集した際に、
実際の外装へ収まるかを検証していない経路があった。
タービン露出型エンジンが船体へ埋め込まれている場合は、実外装の断面と船体内の領域を使い、
寸法を保ったまま収まる機関位置を探す。露出した噴射口へ機関を入れたことにはしない。

機関の定格・長さ・直径・外装の大きさを勝手に変えない。
収まらない指定は理由を示し、不正な機関を稼働可能として計算しない。
旧データの編集元は保持し、修復時にはエラーを解除する。
断面の計算と厳密な収まりの検査はWorker側で行い、入力ごとの同期計算へ追加しない。
給電・伝達路・噴射口閉塞などの既存制限は独立して維持する。

## 対称配置するノズルの機関接続

内部機関の選択が未設定でも、従来は新しいノズルへ接続なしのID `0` を保存していた。
有効な左右の内部機関が既にあっても、対称配置した両ノズルが
`invalid-machinery-reference`・`invalid-drive-profile`・`invalid-rated-input` となる経路を修正する。

未設定の自動選択と、ユーザーが明示した未接続を区別する。
有効な機関が一意、または安定した参照で対応する対称ペアが一意な場合だけ、自動で接続する。
複数の候補から決められない場合は機関を指定するよう案内し、近いという理由だけで接続しない。
接続を指定済みの既存装置は勝手に変更せず、機関の定格入力をノズルごとに二重加算しない。
既に未接続として保存されたノズルは、外装の編集画面で内部機関を選択して再接続できる。
画像に写ったユーザー艦の設計データそのものは未入手で、同じ3つの診断を実AppとCoreで再現して検証する。

## ヴェネターの航空ハッチ

実作例には5基のハッチと閉じたパネル形状が残っていたが、新UIで外装から開閉操作へ進む導線が失われていた。
保存状態を勝手に開放へ変えず、船体タップの情報ウィンドウへハッチの開閉と航空区画の編集導線を戻す。
完全に開いた扉も船体の情報から操作できる。航空区画の編集は内装へ切り替える。
既存の開閉・所有船体との同期・Undo・保存を使い、クリック時に船体の幾何計算を作り直さない。

## 戦闘時の点防御と手動照準

艦の自動迎撃は、部品定義で点防御に指定された兵装だけが担当する。
通常砲の対空追尾能力を、自動迎撃へ参加する条件にしない。
通常砲の威力・旋回速度・射程・連射間隔と、給電・充電・発熱の既存条件を維持する。

公試の照準は敵機・ミサイルも対象にでき、通常砲も手動射撃で命中させられる。
ロックの保持・照準・弾道の命中判定を既存の射撃処理へ接続し、
点防御以外の砲が照準・射撃入力なしに小型目標を自動攻撃する動作をなくす。
艦隊の通常の艦船・艦艇扱いの機体への射撃と、飛行隊の交戦命令は既存の経路を維持する。
旧い全砲参加の迎撃値を再使用しないよう、戦闘用プロフィールを版23へ更新する。
図面から再計算できない旧プロフィールでは、通常砲撃と物理データ・旧版の識別を保持し、
専用点防御だけを分離できない古い自動迎撃値を使用しない。

新しい配置方式では不正な取付方向も編集可能な要求として先に置き、Workerが診断を返す。
兵装の回帰試験は実際の新UIの要求・配置経路を使い、診断の理由・安定ID・Undoと修復可能性を確認する。
旧ハーネスが直接呼んでいた旧配置分岐や、埋没面まで描くことを前提にした期待値を新仕様へ対応させた。
実形状・保存・給電区画の検証は維持している。
戦闘の旧ハーネスには実給電状態を設定し、点防御以外の自動迎撃を前提にした期待値を変更した。
価格更新試験は実Coreの参照速度オーバーレイを読み込み、搭載分離試験は元から0である定員値の仮定を、
プロフィールと搭載プリセット全体の処理前後の一致検証へ置き換えた。
既存の熱停止に入る不適切な合成試験データは有限の熱容量・実ランチャー構成へ直し、ゲームの係数を変えていない。
