# 作例艦の機関と加速度

作例の新規構築時に、次の最大加速度を通常の容積定格で満たす機関を搭載する。通常の保存図面を読み込む際は、この作例の配置処方で利用者の設備を置き換えない。

| 作例 | 最大加速度 | 機関とノズルの関係 |
| --- | ---: | --- |
| インペリアルI / II | 2,300G | 主機1基→主ノズル3基、副機2基→左右各2ノズル |
| アーキテンス | 1,800G | 各ノズルの膨らみに1基ずつ、計3基 |
| CR90 | 2,100G | 各ナセルに1基ずつ、計11基 |
| スフィルナ | 約2,500G | 上部2基と下部1基、計3基の独立機関 |
| MC80ホーム・ワン | 2,100G | 左右の共通機関2基が各5ノズルを担当 |
| MC80リバティ | 2,100G | 共通機関2基が5ノズル／4ノズルを担当 |
| MC75 | 2,100G | 左右の共通機関2基が各6ノズルを担当 |
| MC30c | 2,100G | 主機1基が4ノズル、後部機関1基が1ノズルを担当 |

機関とノズルが連続したナセルに入る構造では、各機関の出力側を対応ノズルのすぐ船内側に置く。直近に必要な実機関を収容できない場合は、ユーザーの追加指定に従い、近接するノズルを共通機関へ統合できる。統合機関も実際の船内容積に収め、複数のナセルの間に浮かせない。ISDとオナガーについては、指定された共通主機から主ノズル3基へ送る構成を使う。

MC系列では、小さなナセルに通常定格の必要容積を収められないため、元の連続した船体内に2基ずつの共通機関を搭載する。ノズル・外形・武装配置を保ち、干渉する内部設備だけを同じ寸法で移設する。大きさの異なるノズルへの出力を等分せず、ノズル径の2乗に応じた比率を各機関の校正中も保持する。

同じ構成の不整合があったドレッドノート級の下段4ノズルと、ネビュロンBの6ノズルも、新規構築では各外筒に独立機関を置く。これら2級に新しい加速度の指定は追加しない。共和国小型輸送艦は左右2開口が同じ連続した艦尾機関区画にあるため、その共通機関を維持する。

機関入力は実容積×`3.4e17 W/m³`、推力は実容積×`1.7e8 N/m³`を基準にする。完成後の艦全体の質量には、機関本体・支持・排熱設備・配電路・動力伝達路も含める。その質量に対する実推力から必要寸法を調整し、表示値への固定補正や通常密度を超える定格で代用しない。

MCの主船体は先に通常の船体構造物へ変換し、外板と骨組みの質量を含めて機関を校正する。生成される船体部品のIDが変わる場合は、外皮の全頂点と武装の実姿勢・取り付け関係を比較する。MC75の内部骨組み計測点の更新は、監査へ旧配列と新配列を明記する。

反応炉から機関への経路は配電であり、他の装備と同様に通常画面には描画しない。容量・距離による損失と発熱は計算する。機関からノズルへの経路は動力伝達路として描画する。

円筒機関・球型炉・箱型炉の接続では、線の中心だけでなく実際の管の端面全体が装置内に入ることを検査する。箱型炉への斜め配線は、端面が収まる最小限だけ接続点を炉内へ移す。装置の位置・寸法・出力や全体の当たり判定を緩めない。

最高速度の公表値は[亜光速の参照表](reference-sublight-speeds.md)で別に管理する。全力推進・全力砲撃・全力シールドが同時に成立するよう発電量を増やさず、実際の運転では給電と厳格排熱の制限を使う。

[生成と物理監査](benchmarks/example-engine-acceleration-refit.json) は、記録された生成元から9作例を各1回新規構築した結果を記録する。機関容積と完成質量から求めた最大加速度は、ISD I/IIが2,300.05G、アーキテンスが1,800.01G、CR90が2,100.00G、スフィルナが2,499.98G、MC系列が2,100.00～2,100.01Gとなった。過去の保存図面や監査結果を今回の生成結果として扱わない。

生成後に加えた航空機の実行時熱処理の修正は、[別の改訂記録](../assets/source/engine-runtime-revisions/table-craft-thermal.json)に記録する。艦艇を生成するCore本体・カタログ変換関数・定数が同一であることと、変更した実行時関数の正確なバイト列を検証する。9作例の実際の生成元SHAと元の監査結果を、新しい実行時ファイルのSHAへ書き換えない。

カタログの物理データを再生成する対象は、表の9作例に限る。残り19件の物理データとその生成来歴は保持し、最高速度の新しい参照は読み込み時のコピーへ適用する。ドレッドノートとネビュロンBの新規機関構成は別の配置回帰テストで確認し、旧カタログの来歴を新しい構築結果として書き換えない。

旧来の簡易定義を使う航空機11機種では、機関の実容積が熱計算へ渡らず、蓄熱容量が1Jとなって発進直後に破損していた。既存の機体質量・公称推力・機関入力・炉出力を保ち、その予算内で通常密度の機関容積と有限の散逸装置を割り当てる。散逸装置の容積は価格へ含め、その消費電力を同じ炉から予約するため、全力時の実推力には給電制約が残る。推定装備であることを保持し、編集可能な詳細図面として扱わない。既存の詳細図面を持つ12機種の電源プロファイルと価格は変更しない。

[航空機の熱回帰テスト](../tests/table-only-craft-thermal.cjs)は、11機種の全力推進、半推力で実際に武装へ給電した運転、散逸装置を破損させた運転を、それぞれ600秒間計算する。正常時は機関を維持し、冷却故障時は蓄熱によって推進能力を失うこと、電力収支と散逸装置の消費が整合することを確認する。
