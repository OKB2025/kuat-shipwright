# 標準ファイターの内部再構築

標準12機種を、ノズル容積から推力を出していた内部配置から、実給電で駆動する機関・反応炉・配電へ組み直した。砲、機体の測定外形、ノズルの出口位置は維持する。公式の内部設計図の再現ではなく、設計局の共通部品モデルに収まるゲーム用の設計である。

- 小さい炉で兵装を優先すると TIE や Vulture の推進に電力が残らなかったため、機体内の実容積を使う反応炉へ変更した。Hyena、Torrent、V-wing も機関・兵装用の炉を再配置・増強した。
- 機関本体の寸法、受入定格、通常カタログの有限な入力密度を明示した。熱計算は厳格運転に統一し、炉・砲・シールド・機関の互換冷却を使用しない。既存の実物の放熱翼と、機体内に収まる小型高エネルギー散逸装置を有限容量の熱輸送路で接続する。散逸装置は実容積・質量・消費電力を持ち、元の有限な発電量を他設備と共有する。
- 炉から機関、砲、シールドへの有限容量の配電を明示し、一方の炉に余裕があっても反対側の機関へ供給できない配置を改めた。
- X-wing は船体より後ろへ張り出す推進管の質量を支える縦通支持材を追加した。管内の支持材を翼の付け根につなぎ、Sフォイルと一緒に動かす。
- 操縦、航法、照準、生命維持、姿勢制御、着陸、レーザーガスは、重なりのない通常の部品として残す。

新規作例の組み立て時だけ、冷却設備を含む完成機体の実質量から部品の入力定格を選定する。散逸設備は実際の配電条件から高温廃熱の最大値を求め、初期試算に20%の設計余裕を見込んで通常の部品として配置する。追加後の実質量と運転条件で再計算し、最終の実容量も検査する。機体の外形・砲・ノズル位置を変更せず、機体内部の空間と固定装置の干渉を検査する。`computeStats` や戦闘時の加速度・速度に機種専用の倍率を加えない。保存済みのプレイヤー設計は再構築せず、部品の削除や定格変更もそのまま保持する。

最大定格、現在の実加速、ゲーム上の速度上限を区別する。設計画面の標準戦闘プレビューは兵装優先・推進35%なので、健全な機体の実加速は上表の35%になる。最高速度の計画値には最大定格と構造・慣性制約を使う。

検証は [fighter-interiors.json](benchmarks/fighter-interiors.json) に改修前 `9beee00` との比較を記録する。全12機種で部品・機関経路の重なり、定格容量、保存再読込、全推進・全兵装・全シールドを同時に要求する30秒の運転について、有限電力の配分・熱制限を確認する。全要求の同時達成を合格条件にはしない。保存設計から散逸装置を撤去した場合は、装置を自動復元せず実際の蓄熱として扱う。熱の検証条件は冷間・無損傷・Sフォイル展開・0.5秒刻みであり、熱平衡が解けた持続定格という主張ではない。

再実行:

```sh
node --test tests/fighter-interiors.cjs tests/craft-example-systems.cjs
node scripts/benchmark-fighter-interiors.cjs
```
