# ハッチを外皮との重なりで決める変更の影響（2026-11-21、PR #122）

ユーザーの決定（2026-11-21）「ハッチ化するなら重なることを条件にする。図るのは無くして。貫通してないのに装甲が無くされるのはおかしい話だ」による変更（`aviationSurfaceHit`、`aviationContact`）を、保存済みの作例で前後比較した。

- 実行：`node compare.cjs <checkout> imperial venator acclamator mc80home executor mandator2 recusant`。変更前（`ce40b90` の `js/core.js`）が `before.txt`、変更後（`cad06cd`）が `after.txt`。変更前は executor の行が出ていない（実行が途中で終わった。原因は未確認）。
- 結果：
  - 質量・加速、既存のハッチの数と開口面積は、6 隻すべてで同じ（既存のハッチは保存された切り口で開くため）。
  - 変わるのは、まだハッチの無い面に新しく開けられる候補（`aviationSurfaceContacts`）。外皮に届いていない面の候補が消え、届いている面も重なった範囲だけになった。例：インペリアル級の格納庫 #83 の下面の候補は 19,916 → 11,617 m²（既存のハッチの開口 11,617 m² と同じ）。マンデイター II の格納庫 #2305 は下面だけが残った（舷側・前後は外皮に届いていない）。
- 作例の性能表と保存済みの設計は変わらないので、再生成はしない。

## 追加の修正：区画の深さ全体で数える（2026-11-21、全体テストで見つけた不具合）

- 見つけ方：全体テストで `tests/ship-dock.cjs` の 3 件目（楔形の船体の上面の格納庫に開口ができる）が、この PR で新しく落ちた。
- 原因：上の変更のあとも、外皮を数える範囲が「ハッチの敷居（既定で区画の高さの中央）から面まで」に限られていた。楔形の船体や斜めの下面では、外皮が区画のもう半分を通るので、区画が外皮を貫いていても開口ができない、あるいは細い帯になる（ユーザーの報告「切り取りで入れたはずなのにハッチ範囲が狭すぎる」と同じ現象）。それまでは、取り除いた 'face' の経路がこの場合を拾っていた。
- 修正：外皮が区画の深さのどこを通っていても重なりとして数える（`aviationSurfaceHit`、コミット `8d3ee0f`）。
- 前後比較（`after-depth-fix.txt`、同じ `compare.cjs`。HEAD で実行）：
  - インペリアル、ヴェネター、アクラメーター、MC80、エグゼキューター、マンデイター II、デス・スター：質量と既存のハッチの開口面積は同じ。まだハッチの無い面の候補が広がる（例：ヴェネター #103 の下面 4,572 → 12,801 m²）。
  - レキューザント級：既存の下面のハッチの開口 1,493 → 4,179 m²。ドロイド制御型（`recusantDn`）は 6,012 → 16,834 m²。開口の大きさは区画の床面の中に収まる（レキューザント級は 167 × 25 m、区画は 290 × 29 m）。
- この 2 隻は作例を作り直した（`node scripts/refresh-examples.cjs --keys recusant,recusantDn`）。そのままではレキューザント級の組み立てが「追加構造維持設備 の船内容積が不足（6 m³）」で止まった。系統の機器を足す回数を、組み立ての最後の系統の呼び出し（エラーを受け止める処理が無く、組み立てが止まる箇所）に限って、通常の回数で許容を超えて足りないときだけ 2 回増やした（`shipRefitAddVolume` の `extraRounds`。物理レビューの指摘で範囲を狭めた）。エラーを受け止めて続ける呼び出し（リフト、不足分の追加 `tryAdd`）は前と同じ回数なので、それらの組み立ては変わらない。
- 作り直した結果（`data/fleet.js` の全数値の比較で、変わったのはこの 2 隻だけ。ほかの 27 隻は全数値一致）：
  - レキューザント級：質量 −0.02%、定格の加速 +0.02%、発艦の速さ（`launch`）0.597 → 1.672（開口が広くなった）。性能表のモジュール 371 → 376（記録では追加構造維持設備の部屋が 14 → 18 個。差の内訳は確かめていない）。
  - ドロイド制御型：質量 −0.02%、定格の加速は同じ（33.91）、発艦の速さ 2.40 → 6.73、対空 356.27 → 356.80（+0.15%、原因は未確認）。
- 経緯の記録：最初の版では回数の追加がすべての呼び出しに効き、ドロイド制御型の加速が +2.6% になった。呼び出し元つきの記録（スクラッチ。コミットしていない）で、この艦の不足分の追加（`tryAdd`、慣性補償 12,216 m³）は基準（`02bcf7b`）でも 381 m³ 足りず（許容 244 m³）、置いた分が全部取り消されていたと分かった（慣性補償の係数 0.975 の原因）。範囲を狭めた今の版では基準と同じく取り消され、加速は前と同じ。この取り消し（不足分を丸ごと捨てる）は以前からの動きで、今回は変えていない。
