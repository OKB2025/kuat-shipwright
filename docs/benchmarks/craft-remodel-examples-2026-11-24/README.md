# 残りの航空機の作例をユーザーのリモデルに置き換え（2026-11-24）

ユーザー：9 機のリモデル設計（ARC-170、BTL-A4、TIE/sa、BTL-B、ハイエナ、V ウイング、ヴァルチャー、V-19、Z-95）を受け取り、「リモデルで作例を揃える」（2026-11-23）に従って作例にした。BTL-A4 Y ウイングは新しい作例 `craft_ywing`（機種 `ywing`）。

- 設計：docs/handoff-2026-11-20/refs/ の arc170・btl-a4・tie-sa・btlb・hyena・vwing・vulture・v19・z95-remodel-2026-11-24.json（受け取ったファイルから作業用のキャッシュ項目だけを除いたもの。`CRAFT_REMODEL_SOURCE`）。
- 組み立ては 11-23 の 5 機と同じ（`craftRemodelDesign`：内部の改装・機体システムの設置・操縦席の位置合わせを行わない。生成は `keepFitPose`）。
- 変えたこと：元の作例で発射管だった位置に置かれたパイロンを発射管に戻した（ユーザー決定「発射管を復活」2026-11-23）。ARC-170 #43/#68、BTL-A4 #25/#26、BTL-B #25/#26、TIE/sa #22、ハイエナ #29/#30、ヴァルチャー #23/#24 は魚雷発射管、ハイエナ #31/#32、ヴァルチャー #25、V-19 #27/#28、Z-95 #31/#32 は震盪ミサイル発射管。向きはそのまま、位置は下の「発射管の位置」のとおり法線方向に動かした。全機で取り付き、口は開いている（浮いた装備 0）。V ウイングは兵装庫なし。
- 読み込みの修正：部品の `pitch`・`roll` が ±180° を超えると 180° に切り詰めていた（js/core.js `deserialize`）。BTL-A4 のリング連結材 #60/#62/#71/#73（roll 225°・315°）が 180° になっていたので、同じ姿勢になる −135°・−45° へ折り返すようにした。ユーザーの保存設計にも同じく効く。データ中で ±180° を超える角度はこの 4 本だけ（data/*.js と data/examples の走査）。

## 発射管の位置（2026-11-23 のユーザー決定「構造物の中へ沈める」に従う）

パイロンの位置のままの発射管は本体の 76〜100% が機体の外に出ていた（最初の測定）。各発射管を取付面の法線方向に ±本体の高さの範囲で 1 cm ずつ動かし、
取り付き（float でない）・口が開いている（`craftMuzzleBlocked` が偽）位置のうち、本体の外に出る割合が最も小さい位置を選んだ（sink2.cjs、positions2.json）。
最初は法線の内向きにだけ沈めたが、BTL-B・BTL-A4・TIE/sa は機体の下に吊る位置で外に出る割合が増えたため（94→100%、76→93%）、両方向の探索に改めた。

| --- | --- | --- | --- |

| BTL-B・BTL-A4 | ctorp #25/#26 | +0.24 | 94% → 60% |

## 許可済みの差異（読み込みの既存の規則、full-diff.txt）

全項目の比較（full-diff.py：部品・装備の全フィールド、ID の両方向、角度は 360° を法）で、形の違いは発射管の種別と位置、薄い部品の厚みの下限 0.02 m だけ。そのほかは、ユーザーが自分のファイルを読み込むときと同じ `deserialize` の規則による。
- `credits`（艦の出典）は読み込まれない。出典は作例の注記（元の作例の作者・ライセンス）に残る。
- 船体構造物の `hullData.paint` の色コードは `neutral` になる（艦の配色の名前だけを受け付ける）。部品そのものの `paint` は残るので見た目は変わらない。
- 帯のない部品の `bandPaint` は捨てられる（描く帯がない）。
- 装備の `label` は読み込まれない。
- 二つのグループに入っている部品は先のグループだけに残る（Z-95 #36/#37、ハイエナ #33、ヴァルチャー #13/#14/#26、V ウイング #35/#36）。
- `detail`・`hullLocked`・`turretSupportRule`・`shieldTarget` は読み込み時の既定値が入る。

メッシュ形状の部品（`form:"mesh"`）：ARC-170 58、BTL-B 74、TIE/sa 39、BTL-A4 66 個（mesh-parts.txt：頂点数と名前）。reference-fidelity-rules.md §2 は mesh を通常の編集可能パーツから外しているが、これはユーザーが自分で作ったリモデル設計の部品で（`imported` なし、名前付き、11-23 の X ウイングのリモデルにもある）、ユーザー決定「リモデルで作例を揃える」により、設計のまま作例にする許可済み差異として扱う。STL の三角形の取り込みではない（元の作例 f00cc2a のこれら 4 機に mesh 部品はない）。
