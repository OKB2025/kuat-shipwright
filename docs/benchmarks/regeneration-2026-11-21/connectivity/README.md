# 格納庫のつながりの規則の比較（2026-11-21、物理レビューの指摘 2・4）

`node conn.cjs <コアのチェックアウト> <設計のリポジトリ> <出力>`：格納庫のある作例 25 隻の保存済みの設計（`0d6476b` の後の設計）を、3 つのコアで計算した。

- `old.json`：`0d6476b`（許容 1.5 m 固定）
- `mid.json`：`7ca2dd6`（軸ごとに max(1.5 m, セル)。箱の事前判定にもセルの許容）
- `new.json`：`ee18e43`（区画を囲む箱どうし（詰め込んだ区画はセルを囲む箱）が 1.5 m 以内の組だけ、探りの距離をセル 1 つ分まで）

結果：

- old と mid／new で違うのは providence と providenceDn だけ。
  - providence：#181・#196 がハッチに通じない → 通じる。Vacc 1,853,038 → 2,690,827 m³。
  - providenceDn：#221・#236 が通じない → 通じる。Vacc 14,851,912 → 21,566,702 m³。
  - どちらも「ハッチに通じていない航空区画」の警告が消える。
- mid と new は全 25 隻で同じ。
- lucrehulk の openA・launch の差は、規則ではなく設計ファイル（`c73840b` で焼き込んだハッチに開口面積を残して作り直した）の差。new の計算だけが新しい設計を読んだ。
- providence の #181 のセルを囲む箱（y 126.68〜204.87）は #24（y 122.88〜137.88）と重なっている（#24 の横ではセルが y 126.7 まで下りている）。#24 の真上ではセル（高さ 5.21 m）が #24 の天井の 4.44 m 上で止まる。置いた箱（中心 y 139.71、高さ 41.7 m）も #24 と重なる。
- 負の例：`tests/aviation-packed-contact.cjs`（箱が 3 m 離れた 2 区画は、セルが 10 m でもつながらない。1 m ならつながる）。HEAD で 2/2、`7ca2dd6` の規則では 1 件目が落ちる。
