# 構造材の量を「重なる相手とだけ」突き合わせる案（2026-11-27。試して、取りやめた）

目的：TIE アヴェンジャー試作機の設計（構造物 406 個）で、公開中の版が iPhone の Safari で最初の計算の途中に落ちる件（ユーザーの報告 2026-11-26。`docs/benchmarks/parts-2026-11-26/avenger-load/`）。最初の性能計算の約 75% が構造材の量（`structuralMaterial`）で、構造物を 1 個ずつ、それまでに合体させた全部と突き合わせている。

## 試したこと
- 各構造物を、船体と、順番が前で箱が重なる構造物とだけ合体させて、増えた体積を出す（数学上は同じ値になるはず）。コミット `c674dac8`。比較のスクリプト `compare.cjs`、点を撒いて体積を数える検算 `montecarlo.cjs`。

## 結果（`compare-big.txt` ほか）
| 設計 | これまで | 新しい計算 | 合計の差 |
| --- | --- | --- | --- |
| TIE アヴェンジャー（412） | 78.3 秒 | 28.1 秒 | +0.026% |
| X ウイング | 2.6 秒 | 1.5 秒 | +0.00007% |
| ゴザンティ | 1.2 秒 | 1.0 秒 | −0.12% |
| インペリアル I | 11.1 秒 | **29.4 秒（遅くなった）** | −0.022% |
| ヴェネター | 18.1 秒 | 12.4 秒 | **+5.6%（構造物 1 個で最大 77%）** |

- ゴザンティで 30 万点を撒いて数えると、差の大きい構造物 1 個（#28）は、これまでの計算 23.2 m³、新しい計算 19.9 m³、点の数え方 13.4 ± 1.0 m³。合体の計算そのものが厳密ではなく、合体させる組み合わせが変わると結果が変わる。
- ヴェネターでは合計が 5.6% 変わり、大型艦では遅くなる例もある。

## 判断
- **取りやめて、元の計算に戻した。** 質量が大きく変わる設計があり、速くもならない設計がある。元の計算の結果を保ったまま速くする別の方法（合体させた表面の場所の索引、途中経過の持ち方、メモリの使い方）を探す必要がある。
- アヴェンジャーの件は未解決のまま。
