# 保存した設計を作例と同じく裏で準備する（2026-11-21）

ユーザーの質問「自作艦を艦隊に含めるのに読み込みに時間がかかるのは何故？」と決定「作例は単に最初に同封されてる完成した設計。つまり作例とユーザー設計はゲーム上での差異はつけない。つまりユーザー設計の艦も作例艦同様、完成した段階で戦闘用データも組み込むのが正しい」。

## 原因
- 保存の直後には、すでに戦闘用データ（艦隊用の性能表・表示用の性能値・艦隊と操艦の 3D モデル）を Worker の端末内の保存場所へ作っていた（`prepareSavedCombat`、v24 から）。
- ただしその保存場所（`ks-built`）は、ゲームの版（`KS_SOURCE_STAMP`）ごとに無効になる。更新のたびに、保存した設計は初めて艦隊に入れたときに一から組み直していた（設計の組み直し・3D モデル）。性能値は計算モデルの版で分けた別の保存場所（`ks-derived`）が残るので、計算し直しにはならない。
- 作例は、起動後に何も操作していない間、裏の Worker で準備している（`KSAssetCache.createPreloader`）。保存した設計はこの対象に入っていなかった。

## 変更
- 準備の対象に、保存した設計（仮保存でないもの、新しい順に 24 件）を作例より先に入れる。保存データを読み出して設計そのものを Worker に渡す（`js/asset-cache.js` の `{key, load}`、`js/app.js` の `savedDesignPreloadItems`）。読めない保存は飛ばす。
- 準備の表示を「保存した設計と作例を準備中」などにした。

## 確認（`browser-check.cjs`、実際の設計画面と Worker）
保存を 1 件置いてページを読み直す → 3 秒で準備の 1 件目（その保存）が終わる → その設計の艦隊用データを求めると 34 ms、出どころは `disk`（組み直した設計）、`record`（性能値）、3D モデルも保存済み（`result.json`）。

## 決めたこと（申し送りの「先に決めること」）
1. 値の出どころ：保存した設計を Worker が読み込み直して計算した値（作例と同じ）。編集中の差分計算の値は使わない（2026-11-12 の物理レビューの決定どおり）。
2. 計算モデルや版が変わったとき：作例と同じく、古いものは使わず裏で作り直す。
3. 保存の大きさ：戦闘用データは保存ファイルには入れず、端末内の保存場所に置く（作例も 3D モデルは端末で作る。`combat.json` の `model` は版の印だけ）。書き出したファイルを別の端末で開いたときは、その端末で裏の準備が作る。
