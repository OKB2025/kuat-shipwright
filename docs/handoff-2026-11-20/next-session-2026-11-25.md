## 2. ユーザーの指示と原則（2026-11-25）

この節は発言の記録と、この部屋の解釈。解釈と書いたところは着手時に実装を読んで確かめ、違っていればユーザーに確認する。

### 2.1 小型艦同士の艦隊戦も成立させる（指示）

「艦隊戦は小型艦同士の戦闘も成立するように作らせるように」

- これまでの調整（wear .05、513 s）は主力艦でしか測っていない。
- 懸念：小型艦のレーザーは射程が短い（CR90 約 1.7 km、点防御 5 km、34TT 球 7.4 km）のに、間合いの候補 `STANDOFFS` は 6.5〜39 km の決め打ち（`js/core.js` `fleetStandoff`）。射程まで詰めず撃ち合いが始まらない恐れ。短射程の砲は命中散布の基準が自分の射程なので近距離でも散る。シールド曲線と wear .05 の小型艦での効き方は未計測。
- 「成立」の判定（この部屋の案。計測前に決めて記録する）：(a) 双方が射程に入って撃ち合う、(b) 時間切れでなく撃沈か撤退で決着する、(c) 所要時間が数分に収まる、(d) 一方が一発も当てられない組み合わせがない（砲のない輸送船は除く）。

### 2.2 間合いは実際に判断して自動で決める（指示）

「艦隊戦の間合いも実際に判断して自動で決める形に。この辺は航空機と同じ」

- 決め打ちの候補表をやめ、その時の状況から間合いを決める。
- 材料（解釈）：自分と相手の砲の射程、距離ごとの届く割合（`gunShotShare`）、命中率（`gunHitChance`）、充電の費用（`weaponInputFactor`）、シールドと船体の残り、速力（詰められるか・離れられるか）。与える量 ÷ 受ける量が最も良い距離を選ぶ。短射程の艦は射程の内側まで詰め、射程で負ける側は詰めるか離脱するかを判断する。
- 航空機は今回の PR で、円を強制せず旋回性能と砲の射程から自然に間合いが決まる形にしてある（計測 `docs/benchmarks/gun-model-2026-11-24/turn-mass/`・`range-sweep/`）。

### 2.3 航空機と艦船に明確な隔絶を設けない（原則）

「航空機と艦船に明確な隔絶を設けない。ただ艦の特性として導き出される運用が違うだけ。なので小型艦も、ものによっては航空機のように接近したり高速で飛び回るものも出来るはず」

- 間合い・機動・射撃の判断は種別で分けない。質量・推力・旋回の速さ・全長・砲の射程と向き（固定か旋回か）・シールド・船体の強さという**特性**を入力にした 1 つの判断で決める。大型艦は遠くで舷側を向け、軽くて速い小型艦は航空機のように接近して飛び回る、という違いは結果として出る。
- いまのコード：`js/core.js` に `craftUnit(u)` を呼ぶ箇所が 79 か所（66 行）。仕分け：(a) 搭載・発艦・編隊など所属としての扱い＝種別のままでよい、(b) 運用の判断（間合い、回り込むか、機首を向けるか、回避、命中散布）＝特性に置き換える、(c) 多数の機体をまとめる簡略化＝残すが境目を種別でなく数と大きさにする。
- 今回入れた「機体の部隊だけ命中散布の基準を変える」修正（750007e）は原則に合わない。**砲の種類・射程で分ける形に直すことは確定**（PR B）。

### 2.4 機首を向ける動きと砲塔の旋回は同じ判断（ユーザーの問い → 合意した整理）

「機首を向ける動きは砲塔を旋回して射界を向けるのと同じ判断になるのでは？」

- どちらも「砲の射線を目標に合わせる」判断。必要な角度のうち砲塔が旋回範囲と旋回速度で受け持てる分は砲塔が回り、足りない分を船体（機体）の回頭が受け持つ。固定砲は「旋回範囲 0 の砲塔」。舷側砲の艦が舷側を向けるのも同じ判断（射界に入る火力が最大になる向きを選ぶ）。
- 船体を回す側の費用：回頭の速さ（質量・全長・姿勢制御）、ほかの砲の射界とシールド・装甲を向ける面が変わること、推力の向きが船体に固定なので進路（間合い）と結び付くこと。
- 実装の見通し（未確認）：艦は `fleetArc` と向きの選択、航空機は機首を向ける機動を別々に持っているはず。「目標に向けられる火力を最大にする船体の向き」を選ぶ 1 つの関数にし、砲ごとの旋回範囲・旋回速度（`weaponTraverseDegS`）と船体の回頭の速さを入力にする。

### 2.5 行動プリセットと統合する（提案。「かも」なので着手時に案を示して確認）

「艦隊の行動プリセットの件と統合して航空機のように決めるのがいいかも。」

- 「行動プリセットの件」（解釈）＝ 2026-11-13 の要件 7「部隊指揮と、教範に基づく行動プリセット」（原文 `docs/handoff-2026-11-15/user-requirements-2026-11-13.md` の 7、整理 `docs/handoff-2026-11-18/README.md` §D、検証する状況は要件 8）。
- 二段にする（解釈）：
  - 上の段＝行動プリセット（意図）：「接近して撃ち合う」「最良の間合いを保つ」「射程の外から支援する」「接触を保って下がる」「護衛対象から離れない」「離脱する」など。距離の数値ではなく、判断の目的と許される範囲（詰めてよい／離れてよい／追ってよい）を与える。航空機にも艦にも同じものを与えられる（§2.3）。
  - 下の段＝間合いと向きの自動判断（§2.2・§2.4）。
- 要件 7 の制約：適用しただけで命中率や防御力に補正を掛けない（7-3）。手動の新しい命令が勝つ、命令変更で位置・シールド・熱・弾薬をリセットしない（7-4）。未発見の敵の情報を使わない（要件 8 の 9）。参考にした教範の名前・版・節・URL を記録する（7-2）。

## 4. 進め方（どの PR でも同じ）

1. 作業開始：ブランチ、`git log -1`、未コミット差分を確認する。この文書と関連文書を読む。**実装済みかどうかは main のコードで確かめる**（`README.md` §1 の表には古い記載がある）。
2. 範囲が未決のものは、案を 1 つ勧めてユーザーに確認する。決まったことは発言の引用と日付を付けて決定ログに書く。こちらで選んだ数値は「こちらで選んだ」と明記する。
3. 実装：大きな共通ファイルは主担当が編集する。`js/` か `index.html` を変えたら `node scripts/update-asset-manifest.cjs` と `--check`。
4. 検証：出力は `/tmp/ks-verify/<日時>-<内容>/`（基準資料の場所へ書かない。多くのスクリプトは出力先を引数で渡す）。変更範囲に対応するテストを実行し、変更前から失敗していたものは main の結果と並べる。UI・Worker・保存に触れたらブラウザで確認するか、未実施の理由を書く。
5. テストの期待値・許容差・基準資料を変えたら、旧値・新値・根拠を変更記録に残す。期待値で不具合を隠さない（今回、二重計上を正解として固定しかけた例がある）。
6. 計算モデルを変えたら版を上げて（`EXAMPLE_PROFILE_VERSION` / `FLEET_PROFILE_VERSION`、`docs/prepared-examples.md`）作例を作り直す → `node scripts/update-craft-costs.cjs`（＋`--check`）→ マニフェスト更新（＋`--check`）。作り直しが要る変更は 1 回にまとめる。
7. レビュー：関係する担当だけ呼ぶ。FAIL は直すか、残す理由を記録する。UNVERIFIED は不足している証拠と一緒に報告する。
8. コミット（末尾に `Co-Authored-By` と `Claude-Session` の 2 行）→ push → ドラフト PR（基準 main）→ `subscribe_pr_activity` → マージ。force-push・amend はしない。
9. 最終報告：実行できなかった項目、ユーザーの判断が要る点（§7）、指示から外れた点を必ず書く。

## 7. ユーザーに報告して判断をもらう点（PR A の最終報告に必ず入れる）

1. **ハイパーイオン砲の充電**：指示は「2 倍」だが、反応炉出力を超えるため `min(P×2, 反応炉/n)` で頭打ち（568 s → 約 682 s）。充電中は反応炉出力の 100% を取るので、サブジュゲイターでシールド・機関に電力が残らない可能性（未確認）。
2. **シールド損耗 wear .05**（こちらで選んだ値）：被弾中は上限の削れ（5%）がシールド自体の減り（4.5%）を上回り、シールドが下がった上限に張り付く。艦のみの艦隊戦 612 s（.04）→ 513 s（.05）。
3. **対空評価値**：点防御が 1 発/秒になった結果、レーザー以外の砲の aa が 2〜5 倍（oct40 0.69 → 2.18 など）。艦載機戦への影響は未計測。旧来の釣り合いに戻すか現状を採るか。
4. **Z-95**：レーザーが口径 0.10 m の円柱になり 1.2 t → 0.152 t、加速 3,406 G が建造目標 3,330 G を超える（`fighter-interiors` テスト 12 は失敗のまま）。質量の決め方を直すか、目標を直すか。
5. **エンブレムの向き**：旧保存では向きが変わる（移行なし）。移行を入れるか。
6. **B2 と F1 の順**（§6）。
7. **「成立」の判定基準**（§2.1 の案でよいか）と、間合いの判断材料・行動プリセットの二段構成（§2.2・§2.5 の解釈でよいか）。
8. 未修正で残っているもの：(1+c) を艦全体の平均で掛けている、ISD が艦載機ありで 86 s で電力喪失する件は main との比較未実施。
