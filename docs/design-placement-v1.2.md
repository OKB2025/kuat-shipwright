# KUAT SHIPWRIGHT 新設計UIと構造物接続 v1.2

対象: `OKB2025/kuat-shipwright`。作成・改訂日: 2026-11-08。

艦艇を主領域に表示し、下部から部品選択・調整を開く設計UIへ移行する。
構造物を追加元として選び、編集上の親子関係と実形状の接触を区別する。
既存Core、WebGL、YardEngine、編集コマンド、安定ID、保存外枠v3と
`surfaces.version = 4` を継承する。戦闘UIや機器係数の再調整は対象外。

## 今回の依頼で確定した仕様変更

当初のv1.2指示書の「骨組み廃止」は、その後のユーザー指示で変更された。
**骨組み重量、骨組みの強度寄与、縦強度による加速・推進入力制限をすべて現状のまま保持する。**
構造維持装置の効果や既存設定も保持する。重量除去・密度補正・代替効果の追加は行わない。
親子・実接触による接続診断の追加を、強度・加速モデルの変更として扱わない。
既存120区間の断面評価は強度計算として残るため、新しい接続診断が正常でも
既存の強度上限や断面警告が自動で解消するとは限らない。

最初の依頼は文書のみだったが、続く指示でゲームコードの変更とPR作成まで承認された。
マージ・公開は今回の範囲に含めない。

## 外装の親子操作

外装は構造物・武装・推進装置・指揮通信設備をすべて同じ親子接続の操作で扱う。
配置画面でタップした構造物が追加元となる。面配置の取付面・位置・法線もタップした実面から取得する。
追加元を先に選ばないと配置できない操作にはしない。確定前に追加元・面を表示し、再タップで変更できる。
構造物以外の外装は従来の通常取付を保持し、構造物専用の3方式は表示しない。

親の削除は、明示的に削除する対象を除いた実接触関係をまとめて評価する。
親以外に接触先のない子は削除し、他の構造物への接触がある子は残す。
その接触先が同じ親の別の子でも、消失参照・相互親子・循環を作らない。
残存する接触群に必要なら代表ルートを定め、有効な単一親へ組み直す。
削除・参照更新を一つのUndo操作として記録し、取消やUndoで元へ戻せるようにする。

コピー・貼り付け・複製は子孫を含むのを標準とし、武装などの外装子も一緒に扱う。
複数選択で重複した子は一度だけコピーし、新IDと内部の親・取付参照を対応させる。

## 追加指示: 鏡映の実面補正とノズル支持台

鏡映候補は、対応する親の実面を検出したら、その面ID・実接点・法線・接線を一組で採用する。
単純反転した座標を残さない。現在は反転点の前後各10cm、計20cmの既存近傍探索を使い、
対応する面がこの範囲にない場合は修正を案内する。他の親・反対面へ自動で飛ばさず、
接触距離の許容差は広げない。水平・垂直の艦基準姿勢、武装の明示した上面／下面姿勢を保つ。

エンジンノズルの斜面取付には、武装の支持台と同様に隙間を埋める閉じた支持材を生成する。
支持台の根元は左右・上下の対称性を保つ4辺とし、親の実面に沿わせるために必要な分割だけを残す。
円周方向の多分割を支持台へ持ち込まず、ベル本体と噴射口の形状は維持する。
ベル本体の位置・寸法・推力方向、機械の定格・給電・伝達路・機器IDは保持する。
支持台は描画専用面や別の隠し部品にせず、元ノズルの形状として表示・選択・接触・保存へ共用する。
既存図面のノズルも対象とし、接続の成立は実形状で確認する。

支持材の実体積は、既存構造材との重複を除き、武装支持台と同じ材料密度0.3t/m³で別に集計し、既存構造材のHP・費用則を使う。
機関の機能容積・定格出力へ支持材を混入しない。追加材料の質量とそれに連動する熱容量・加速等の差は
意図した変更として記録し、骨組み重量・縦強度の式や係数は据え置く。
派生艦艇プロフィールは計算モデルの版を更新し、図面がある旧データは新Coreで再生成する。
図面のない旧スナップショットは再計算が必要な読み取り専用データと明示する。

## 追加指示: トレンチの集約兵装

エグゼクターやマンダトール等の大量兵装は、トレンチを開く操作から砲種ごとの基数を入力できるようにする。
入力は既存の砲種定義1基を単位とする左右合計とし、連装砲の砲身数を重ねて掛けない。
左右への配分を表示し、左右それぞれに前後へ延びる給電・充電区画を作る。

砲塔の外装モデルは生成せず、保存・配置・戦闘の情報を砲種と左右の砲列の単位でまとめる。
門数に比例して部品・メッシュ・戦闘モジュールを増やさない。発射位置はトレンチに置き、
射界、給電不足、蓄電量、損傷、消費電力と発熱を既存の兵装計算へ接続する。
砲塔を描画しないことを質量・費用・充電容積の免除にはせず、既存の定義と基数から集計する。
発射エフェクトの表示数と実際の火力・消費エネルギーを区別する。
砲座は幅・高さを保つ行として配置できることを、基数分のオブジェクトを作らずに証明する。
行ごとの個数・間隔から実在する砲座中心を最大8地点選び、所有者の実メッシュへ投影して発射点とする。
一部が遮蔽された行は開いている地点の重みだけを射撃に使い、実際の発射位置もその地点から選ぶ。

設定・変更・撤去はUndo/Redo、Workerの世代照合、保存と再読込へ接続する。
既存作例の通常砲塔を無断で削除・変換せず、新しい集約砲群の設定であることを画面に示す。
適用前の検証に失敗した場合は理由を表示し、元の図面と操作履歴を保つ。

## 配置と保存の契約

|対象|許可方式|条件|
|---|---|---|
|外装構造物|水平・垂直・面|最初のルート以外はタップ先を親にし、確定前に実接触を検証する。|
|外装の推進・兵装・指揮通信|通常取付|タップした構造物の子とし、既存の面法線・姿勢・支持台・射界・干渉規則を継承する。|
|内装可変部品|切り取り・容積維持|部品定義の機能寸法、開口、連結性、空隙、干渉条件を検証する。|
|内装固定機器|通常配置|実寸の剛体変換だけを許し、切断・圧縮・密度変更しない。|

表示カテゴリだけで能力を推測せず、部品定義の能力でUIとCoreの双方を検証する。
水平は艦基準姿勢を保持して親に接する下面を成形し、垂直は直立を保って親側面を成形する。
面配置は既存法線・接線に従い、専用フィットを追加しない。艦基準軸はX前後、Y上、Z左右。
親の実際の切削・曲面・開口を使い、別の構造物や反対面へ無断で対象を変更しない。
張り出しを許すが、接触ゼロ、点・辺だけの偽接続、ゼロ厚み、開いた形状は成功にしない。

### 重なりによる接触（2026-11-11 ユーザー決定）

構造物が親と実際に重なっていれば、配置方式（面・水平・垂直・通常取付の形状部品）を問わず接触とみなす。重なった部分は構造の合併（`structuralMaterial`）で質量・容積を一度だけ数え、露出面の切り抜きで表示しない。部品の移動・膨張・支持材の追加はしない。判定は `placementContact` → `placementOverlapContact`（`js/core.js`）。`eps` は面接触判定 `placementTriangleContact` が同一平面とみなす距離許容差（`placementEpsilon×4`）と同じ値。

|限界|値|意味|
|---|---|---|
|最小の厚み|重なり領域の全方向の寸法 > `eps`|これより薄い重なりは面接触判定で「触れている」と同じ扱いになる範囲で、重なりとは数えない|
|最小の体積|重なり体積 > `eps × 面接触の最小面積`（`max(eps², 寸法² × contactAreaRelative)`）|面接触の最小面積を許容差の深さだけ押し込んだ体積|
|埋没の上限|なし（2026-11-11 ユーザー決定）|99.95% が親に埋もれていても接続する|
|完全に埋没|親の外の体積 ≤ `max(最小の体積, 部品体積×1e-9)`|親の外に自分の材料がない部品は従来どおり `contact-zero`（接続しない）|

実際のすき間、点・辺だけの接触、最小値に届かない数値上のかすり、親の中に完全に埋もれた部品は従来どおり `contact-zero`。水平・垂直の切り取り成形が作れない場合（`surface-missing`・`minimum-thickness`・`contact-shape`・`geometry-complex`）でも、要求形状が上の条件で親と重なれば、閉じた要求形状のまま接続する（`placementOverlapFallback`）。境界の検査は `tests/placement-curved-hull-surface.cjs`。

### 削りと接続（2026-11-11 ユーザー決定）

ユーザーの考え方：船体が土台の本体で、構造物はそこに材料を足し、削り（削る）は足し合わせた本体を削る。**実際にまだ触れている構造物を、削りが切り離してはならない。**

ユーザー決定（2026-11-11）。1〜5 は目標のモデルで、段階的に実装する。

1. 船体や親構造物を移動・回転・拡大縮小したとき、取り付けた構造物は剛体のまとまりとして追従し、形を保つ。親の形状へ再成形しない（後続段階。現行の ATTACH-02 の再成形はこの段階で置き換える）。
2. 新しい削りは、交差するすべての構造物（板・翼・パネルを含む）に効く。作例・保存済みの船体専用の削りは船体専用のまま。個別に「すべてに適用」へ切り替えられる（後続段階）。
3. 削りが構造物を切り離したり、固定機器（反応炉・機関など）に当たったりしても、削りは実行し、点検に警告（選択リンク付き）を出す。自動で移動・削除はしない。
4. トレンチ・面取り・平面台形の削りは船体専用の形状道具のまま。削るメニューは立体カッター（箱・円柱など）の単一の道具になる（後続段階）。
5. 重なりは見た目では削らない。質量は一度だけ数える（実装済み、「重なりによる接触」）。

段階 0（実装済み、`tests/placement-cut-keeps-connection.cjs`）：

|項目|規則|実装|
|---|---|---|
|位置決めキー|親の材料だけが変わる変更（船体所有の削り `hullData.cuts`・トレンチ・立体カット・切り欠き `subs`・ハッチ、および構造物に効く艦レベルの立体カット）では子を再計算（移動・再成形）しない。子の実接触だけを調べ直す。親の姿勢・外形が変わったときだけ再計算する|`placementPositionKey`、`refreshPlacementGeometry` の `removalOnly`。`placementDependencyKey` は変えない（`interiorEnvelopeKey`・装備キャッシュが使う）|
|面IDは手がかり|保存した `hostSurfaceId` は位置に基づく番号（面：船体の4分割：連結成分：トークン）で、削りで番号が変わり、消えたり重複したりする。消えた・重複した面IDでは保存した姿勢を保ち、親との実接触（面接触か重なり）で判定する。失敗は実際の接触ゼロだけ。アンカーの下の面が1つに決まれば面IDを付け直す|`placementSurfacePatch`（一意のときだけ）、`placementRebindSurface`、`placementEquipmentSurface`、`fitAttachmentSurface`。今回の要求で新しく選んだ面IDが存在しない場合（古い選択）は従来どおり `surface-missing`|

|成形形状|水平・垂直の切り取り成形（`fitPlacementContact`・`placementOverlapFallback`）は、子を置いた時点で親にあった削り（船体所有の削り・トレンチ・立体カット・切り欠き・ハッチ）を含み、その後に加えた親自身の削りを除いた親（`placementUncutParent(ship,parent,true,fitRemovalIds)`）に対して作る。置いた時点の削りの ID は配置のたびに `placement.fitRemovalIds` に記録する（新しいタップ・移動のとき。再計算・再読込では記録を使う）。記録のない保存データは今あるすべての削りを含める（従来どおり）。記録した削りそのものを編集・削除した（同じ ID で大きさを変えた、など）ときは、親が変わったときと同じく子を作り直す（main と同じ。子ごとに記録した削りとその内容のキー `placementFitRemovalKey` で判定）。ID のない削りは内容（と同じ内容の中での順番）で名前を付けるので、前の削りを消しても名前は変わらない。既存の凹みに置いた子は main と同じ形になる（床まで伸びる、床で切る、小さな穴を埋める）。構造物に効く艦レベルの立体カットは子も削るので、子の範囲に届く艦レベルのカットが変わったときは子を作り直す（`placementChildCutKey`）。成形形状は子の要求、親の姿勢・外形（位置決めキー）、子に届く艦レベルのカットだけで決まり、編集中・再読込・Worker の候補で同じ形・同じ質量になる。接触の判定は削った実際の親で行う。削りを狭めても広げても、残した子の形は新しく解いた形と同じで、質量・容積・価格も一致する（再読込を挟まなくてよい）。重なりは接触で、質量は構造の合併で一度だけ数える|`solvePlacement`、`tests/placement-cut-keeps-connection.cjs`「narrowing a cut」「does not depend on history」|
|親が動いたとき|ユーザー決定 1（剛体追従）のこの段階での最小形：親が動いて子の再計算が失敗したとき、子は保存した親ローカルの基準点で親と一緒に平行移動し、その位置で判定する（削りで離れていれば警告、そうでなければ失敗）。切り離された子が親の移動で赤くなることはない。回転・拡大縮小を含む完全な剛体追従と再成形の廃止は段階 3|`placementCarryToParent`|
|計算量|親ごとのキーは更新 1 回につき 1 度だけ計算する。材料だけの変更では、子の周りの親の三角形と子自身の三角形が変わっていなければ接触を測り直さない（周りの範囲は子の寸法の 1% と `8×placementEpsilon` の大きい方）|`placementParentKeys`、`placementLocalParentHash`|
|浮いた装備|面IDが消えても実形状に触れていれば着座のまま。足元が削られて浮いた装備は `floatingFits` に出す（以前は `float` を理由に飛ばしていた）|`groundingStats`|

物理への影響：艦レベルの立体カットがある設計だけ、船体の材料容積・質量・船体価格が減る（同じ形の船体所有の削りと一致。例：10 m の箱のカットで 872.99 m³、質量 −174.60 t（×0.20）、船体価格 −524（×0.6））。装甲は従来どおり削った面にも付く（ΔA 336.77 m² × 厚さ 0.5 m × 7.8 = 1313.40 t、変更なし）。重なった構造物と船体を同じカットが通っても、材料の合計は合併の体積と一致し二重に引かれない（`tests/solid-cut-scope.cjs`）。2026-11-11 時点の作例 28 隻には艦レベルの立体カットがなく、組み立てた質量・容積・価格は変わらない。`COST_MODEL.version`（17）と `FLEET_PROFILE_VERSION`（23）はこの段階では上げない：作例の再生成（`data/fleet.js`・作例の combat.json の costVersion 17）はユーザーの判断で後回しにしており、版だけ上げると作例と不一致になる。保存済みの艦載機は、艦レベルのカットがあっても読み込み時に保存時の質量・推進質量・価格のまま一貫する（価格だけ再計算すると質量と食い違うため、上げるときは `COST_MODEL.version` と `FLEET_PROFILE_VERSION` を一緒に上げ、`cleanDesignCraft` に設計図から作り直させる）。版の更新は最終的な作例の再生成と同時に行う。

段階 1（接続は接触の網、`tests/structural-connectivity.cjs`）：

|項目|規則|実装|
|---|---|---|

|接地|明示配置の構造物は、親に限らず、接地しているどの構造物に実際に触れていても接地。親との接触を失っても接地した隣に触れていれば赤枠も切り離しの警告も出ない。診断は `connected:true`、`via:'contact-graph'`、`parentContact:false`、`neighbours`。外装機器は従来どおり親への取付で判定|`groundingStats`、`placementDiagnostics`|
|成形が作れない接触|置いた後に記録した凹みが動いて壁が子の足元を横切るなど、切り取り成形を作り直せなくても、編集していない子が保存した位置で親に実際に触れていれば、要求形状のまま接続とする（赤い修復状態にしない。再読込でも同じ）。main でも赤だった既存の動作の改善|`placementStoredPoseKept`|

`refreshPlacementGeometry` の戻り値 `severed` は「親との接触を削りで失った」部品の一覧で、点検の警告（`S.severed`）は接触の網で接地していない部品だけを出す。

以前の規則「形状編集で面が失われた場合は元定義を保持し、再接続を案内する」（下記・ATTACH-03）は、面IDが消えても実接触があれば接続を保つ、に置き換えた（2026-11-11、レビュー対象の仕様変更。`tests/structure-placement-modes.cjs`・`tests/fit-placement-attachment.cjs` を更新）。

切り取りの有効形状は要求形状と使用可能領域の交差、能力は有効容積から求める。
容積維持は使用可能領域への完全内包と要求容積の維持に加え、機能上の制約を満たす。
空間総容積だけで成功にせず、失敗時に切り取りへ無断変更しない。

編集元形状・モード・親ID・安定面参照・親ローカル基準点・接触側・親子世代・モデル版を保持する。
一時メッシュを唯一の正本にせず、同じ入力から同じ有効形状を再生成する。
旧図面は元の形状・姿勢・機器設定を維持し、明示的に新方式へ変更するまで自動成形しない。
親の意図的削除は上記の実接触による削除・残存判定を行う。
形状編集で保存した面IDが失われても、子は保存した姿勢を保ち、親との実接触で接続を判定する（2026-11-11 改定、「削りと接続」）。実接触がなくなった場合だけ再接続を案内する。
循環・自己参照を拒否し、部分コピーや別艦への貼付で外部IDへ誤接続しない。
親の移動・回転・形状変更は依存する子孫だけに伝え、まとめて1回のUndo/Redoにする。

## UIと非同期処理の契約

右側の全長・質量・出力・加速はCore/Workerの実値を使い、計算中・最新確定・失敗を区別する。
下部に外装／内装・新規配置・編集を置く。既存の保存、Undo/Redo、表面、装甲、砲列、
内部設備、ユーザーパーツ、頂点編集への導線を保つ。内装切替は可視化の変更として扱う。
追加元の名称とハイライト、変更操作、成形側・接触・干渉・検証中のゴーストを示す。
確定・取消・戻るをスマホの縦横とセーフエリアでも操作できるようにする。

ドラッグ・スライダー中は軽量プレビューとし、確定時に最新要求を厳密検証する。
計算中も移動・削除・選択・カメラ・取消を受け付ける。要求の設計ID、操作ID、部品ID、
親ID、親子の世代、モデル版を再照合し、後着結果で復活・巻戻し・異世代混合を起こさない。
カメラを再計算キーにせず、変更のない枝や開くたびの全艦再生成を避ける。
