     - ユーザーの補足（2026-11-15、3 回目。原文のまま）：「面はその方向一帯。」「ハイパースペースから出現して停止する位置の間に敵艦がいる場合はぶつかるので無理という話。」「惑星も同様」
     - 入口の面は、出発した星系の方向の側一帯（戦術空間の外側のその向きの面全体）。到着位置は、その面から星系の内側へ引いた線の上で選ぶ。
     - 超空間から出現した点と停止する位置の間に敵艦があると、ぶつかるので、その位置は選べない。敵艦の手前までは選べる（敵のそばには出られるが、敵の向こう側には出られない）。
     - 惑星などの天体も同じ：出現点と停止位置の間に天体があれば、その奥は選べない。
  8. 「天体自体は今のサイズを基準に。」
     - 天体の半径はいまの値（`SYSTEMS[key].planet.radius`）を基準にする。縮めるのは天体どうしの距離のほう（決定 2）。
  9. 「移動時間はだいぶかかっていい。結局時間を早くする機能があるので」
     - 移動時間を短くするために距離を詰める必要はない。時間を早める機能（艦隊戦の再生速度、公試の早送り）で補う。
  10. 「小惑星帯は通常の艦の衝突と同様にダメージ、航空機は即死クラス」「基本TTクラスなら一撃で消える」（2026-11-15、3 回目）
     - 艦が小惑星にぶつかると、艦どうしの衝突と同じ扱いで損害を受ける。航空機（艦載機）は当たれば失われる。
     - 小惑星は、テラトン級（TT）の威力の一撃で消える。それ未満の威力の扱い（何発かで消えるのか、消えないのか）は未確認。
  11. 「現状の空間をそのまま広げてそこに天体を配置するというだけ。」「ハイパースペースに入る、出る時の演出で惑星が中サイズの球体に見えるくらいの位置まで作られてることは把握してる」（2026-11-15、4 回目）
     - 新しい空間の仕組みは作らない。いまの空間（惑星を原点に置いた座標。公試・パトロール・艦隊戦が使っているもの）をそのまま外へ広げ、そこへ衛星・ガス巨星・小惑星帯を置く。
     - 根拠としてユーザーが挙げた現状：超空間への突入・離脱の演出（`trial.jump` の tunnel → exit → brake）は、惑星が中くらいの球に見える距離から到着高度まで艦を動かしている。空間はその距離まですでに使われている。
     - したがって作業の中心は、(a) 星系データに天体の一覧と位置を足す、(b) 描画が天体を複数受け取れるようにする、(c) 艦隊戦の開始位置・到着位置・交戦開始の規則を広い空間に合わせる、の 3 つ。座標系の作り直しや、場面ごとの空間の統合のための大改修はしない前提で見積もる。
     - 主担当がまだ確かめていないこと：演出で使っている最大の距離の実際の値、その距離での描画と当たり判定の精度（単精度）、艦隊戦が同じ座標をどこまで共有しているか。着手時に測って報告する。
- まだ決まっていないこと（実装の前に案を出して確認する）：
  - 距離の倍率の具体値。「結構近め」と「移動時間はかかっていい」の両方を満たす値を、主な星系について表で出す（衛星の軌道半径、小惑星帯の位置、全速での所要時間、早送りでの実時間）。
  - 到着位置の細部：線の向き（面に垂直か、選んだ点へ向かう向きか）、停止までの距離、味方艦や小惑星帯が途中にある場合の扱い、敵艦・天体からどれだけ手前までを選べるか。
  - 射撃で交戦が始まる規則の細部：点防御の迎撃や超兵器、艦載機の射撃も「射撃」に数えるか。交戦が始まる範囲（その星系の全艦か、近くの艦だけか）と、終わり方。いまの艦隊戦の開始処理（同じ星系に入ると戦闘になる）と AI の動き（先に撃つ条件）の作り直し。
  - 小惑星の細部：TT 未満の威力（点防御、艦載機の武装）の扱い、ターボレーザー以外（イオン砲、ミサイル・魚雷、超兵器）で消えるか、小惑星の大きさと数、艦がぶつかったあと小惑星が残るか、センサーへの影響。
  - 公試・パトロールの開始位置（いまは惑星の低軌道から始まる）を、共有する空間のどこに置くか。

  1. 試験航行：母艦から作例の小型機（設計そのもの）を発艦させ、AI で飛ばして撃たせ、着艦させる。1 機に操作を移す。

### 電源喪失を戦闘不能にしない（2026-11-16 追記、PR #111 のあとの PR で実施）

- **ユーザーの指示（原文）**：「電源喪失は戦闘不能扱いではないようにしよう。単に動けなくなり、シールドを失い、発電量がゼロになり、星の重力に少しずつ引かれていく」
- **確認した点**：PR #111 には入れず、別の PR で行う（「Separate PR」）。電源のない艦は、充電済みの兵装も撃てない（現在の規則のまま、「No firing」）。
- **現状**：使える電力が 0 になると `syncPowerLossDisabled` が `u.out='電源喪失'`（戦闘不能）にし、命令を待機に変える。`u.out` は約 80 箇所で見ている（勝敗の判定 `fleetEffective`、照準、発艦、ジャンプなど）。重力のある戦場では、戦闘不能の艦は `hullFall`（0.6 m/s² で沈み、深さ 60 km で焼失）で落ちていく。仕様は `docs/calibrated-propulsion-and-power-loss.md`、試験は `tests/power-loss-navigation.cjs` など約 12 ファイル。
- **方針案**：電源喪失を `u.out` から切り離した別の状態（例 `u.powerLoss`）にする。艦は戦場に残り（狙われ、勝敗の数に入る）、推力・発電はゼロ、シールドは消えていき、重力のある戦場では `hullFall` で落ちる。電源が戻れば解除。ジャンプの取り消し・発艦の禁止・充電済みの兵装を撃てないことは今の規則のまま。艦載機の飛行隊（`s.disabled`）の扱いは艦載機の PR と合わせて決める。
- **実施**：`outOfAction(u)`（電源喪失以外の理由で航行不能）を追加し、艦隊戦の勝敗（`fleetEffective`）、試験航行・パトロールの終了、敵の残数の表示で `u.out` の代わりに使う。動けない・撃てない・ジャンプしない・シールドが消える・重力で落ちる、は既存の航行不能の状態のまま。全艦が行動できないときは、にらみ合いで終える。自艦の表示は「電源喪失（航行不能）」。`tests/power-loss-stays-in-battle.cjs`。
- **PR #111 での扱い**：公試のスポーン戦で自艦が約 10 秒で「電源喪失」になり戦闘が終わる揺れ（このブランチ 8 回中 1 回、main 5 回中 0 回、決定前のコミットでも発生）は、既知の問題として残す。この PR で、電源喪失で戦闘が終わらなくなる。

### 当たり判定を船の外面に（2026-11-16、PR #112 に追加）

- **ユーザーの指示（原文）**：「当たり判定は船の外面に出るように。デススターなどで試したが当たり判定が遠すぎて赤道トレンチに入る前に衝突した」
- **原因**：艦どうしの衝突は船体の外接箱（`hullOverlap`、全長・高さ・幅の半分）で判定していた。デス・スター（直径 160 km）の箱は球面より大きく外へ出るので、トレンチの床より上で衝突していた。試験航行の弾の当たりも楕円体（`segShip`）だった。
- **実装**：
  - 艦ごとに「外面の半径の地図」を作る（`Core.hullRadialMap`）。描画用の中心から各方向に、いちばん外側の面までの距離を記録する。格子は通常 1°、全長 20 km 以上の艦は経度 0.5°・緯度 0.25°。
  - 地図は Worker が描画メッシュ（内部機器・開いたハッチ・標的マーカーを除く固形のメッシュ）から作り、応答 `radial` で返す。ページ側は艦の鍵ごとに登録する（`Core.setHullRadial`）。デス・スターで約 3 秒、1 モデルにつき 1 回。
  - 衝突は外接箱を粗い判定として残し、そのあと相手の地図に対して自艦の外面の点（地図があれば 26 方向、無ければ箱の点）が内側に入っているかで判定する（`hullRefine`）。赤道トレンチの方向では半径がトレンチの床になるので、トレンチに入れる。
  - 試験航行の弾（自艦の弾・見える敵の弾）も、地図があれば外面で当たる（`radialSegment`）。
  - 地図の無い艦（艦隊戦の性能表だけで動く艦）は、従来の箱・楕円体のまま。艦隊戦の決定性は変わらない。
- **測定**：デス・スターの地図で、赤道の半径 76,850 m（トレンチの床）、緯度 10° で 80,100 m。
- **試験**：`tests/hull-outer-surface-contact.cjs`（4 件）。
- **ブラウザ**：試験航行の艦（自艦・オナガー・アークワイテンス）に地図が届くことを確認。トレンチを実際に飛ぶ画面確認は未実施。
- **近似**：中心からの放射方向で一番外の面を取るので、中心から見て外面の陰になる窪み（深いハンガーの奥など）は埋まった扱いになる。
