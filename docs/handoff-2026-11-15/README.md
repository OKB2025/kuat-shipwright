### 削りの焼き込み（最優先の構造変更）

- ユーザーの指摘：「カットもカットに図形を使うというだけでカットされたらその頂点をもつ単なる構造体、船体構造体に過ぎないはず。わざわざ別図形化してる？」
- 決定（2026-11-13）：**「焼き込み、分かれた塊は別の部品にする」**。
  - 削りを確定した瞬間に、当たった構造物・船体を、削った形のメッシュ（頂点）で置き換える。削りの図形は切るためだけに使い、別に保存して毎回引き算する現在の方式をやめる。
  - 削りで分かれた塊は、それぞれ独立した構造物にする（個別に接続判定・選択・削除できる）。
  - 後から動かすのは Undo。作例の削りも焼き込んで作り直す。
- 関連する決定：「容量を保つ方式はそのまま、切り取りは切り取り」（内部区画の「容積を保つ」配置方式は変えない。削りは削りとして扱う）。
- 関連する決定（2026-11-14、段階 B のとき）：「削り自体も実際に構造物に焼き込す形式にするなら現状の接触判定で十分なはずだ」。これを受けて、削りで切り離された警告（`severed`）と置いた時の削りの記録（`fitRemovalIds`・`fitRemovalHashes`）は #105 で廃止済み。**焼き込みが入るまでは、削りで離れた構造物も赤枠（接地なし）になる**（`docs/design-placement-v1.2.md` の既知の限界に記載）。
- 現状の仕組み：艦の `solidCuts`・`cuts`・`trenches`・`subs`、船体構造物の `hullData`、構造物ごとの削りを、形を作るたびに引き算している（`js/core.js` の `solidCutsContain`、`compiledSolidCut`、`structTriangles` まわり）。構造物の自由多面体は `form:'mesh'`。
- 影響が大きい点：保存形式（古い保存データの移行）、Undo/Redo、Worker の準備済み設計、作例の全再生成、削りを前提にした試験。regression-reviewer と、保存形式なので Opus/high の追加確認が要る。
- **PR #110 のデス・スターは削り（皿の井戸、子午線トレンチ）を多用している**ので、焼き込みを入れるときは一緒に作り直す対象になる。
- 関連する不具合（未修正）：艦の削りで分かれた構造物が、埋まっている側の破片を通じて「接地している」と数えられる。焼き込みで塊が別部品になれば解消する見込み。
