### A. 排熱の発熱源の整理（次に着手）

ユーザー決定（2026-11-18）「排熱は炉心の稼働と電力損失(＋イオン被弾)のみで求めるようにしよう」と、その後の 3 つの回答：

- **残す発熱源**：炉心の稼働、給電経路の損失（電力損失はこれだけを指す）、イオン被弾。
- **無くす発熱源**：武装（いま 25%）、シールド（30%）、エンジン（約 5%）、艦内設備（100%）、超兵器（12%）、通常被弾の熱。
- **炉心の発熱率を上げる**：発熱の合計がいまと同程度になるようにする（いまは 4%）。率は作例の発熱の内訳を測って決め、ユーザーに提示してから入れる。作例の冷却設備と戦闘中の熱の挙動をほぼ変えないのが狙い。
- 着手点：`js/core.js` の `HEAT.waste`、`heatWaste`、`shipThermalCruiseModel` の周辺、`hyperChargeHeatCapW`（武装の熱を引いている）、`heatSwCharge`。文書は [../heat-converters.md](../heat-converters.md)、[../thermal-governor.md](../thermal-governor.md)。
- 未回答のまま残っている関連の問い：停電（電力喪失）のあと蓄熱に上限を設けるか。イオン被弾で容量の 200 倍を超えて熱が積み上がる。イオン被弾を残す今回の決定で、この問いはそのまま残る。

### E. 各砲ごとの射撃（2026-11-18 の決定）

- 砲塔は 1 基ずつモジュール（位置・射程帯・威力・電力・乗員・耐久）として性能表にある。砲塔数：インペリアル I 級 49、ヴェネター級 54、デス・スター 276、エグゼクター級 2044。
- 方式：
  1. その瞬間に撃つ砲のうち、命中する砲を確率で選ぶ（確率は空間での命中判定の値）。
  2. 命中する砲だけ、ターボレーザー／イオン弾の飛び方を求め、シールドの侵徹量・装甲の貫通・区画の破壊を計算する。
  3. シールドで防がれる弾は、まばらに着弾するように見せ、その分だけシールドを減衰させる。
  4. 当たらない弾は見た目だけ散らす（計算しない）。
- 壊れた砲・給電の切れた砲・乗員の足りない砲は撃たない。
- 自艦を狙う弾もこの方式に揃えてよい。比較（2026-11-18）：全力の加速で左右に振れ続ける CR90・アークワイテンズ・インペリアル I を 5〜35 km で撃つ 60 件で、Core の命中率と、1 発ずつ飛ばして交差を数えた割合の差は最大 1.6 ポイント。急加速・急減速と手動の不規則な動きは未比較。
- 艦隊戦の結果が変わるので、決定性の記録（`tests/helpers/fleet-battle-determinism.json`）は取り直しになる。
