# 全艦共通の機関母線と、持続巡航に合わせた冷却（v25、2026-11-16）

## 決定（ユーザーの指示）

- 「基本的に最高速度の6〜8割が持続的な巡航速度になるように各艦の排熱装置を調整」「排熱装置の能力をさらに減らそう」
- 「そもそも出力値のほとんどがエンジンに行くならそのようなモデルになるのでは？」「おそらく分離されたリアクターからの出力により速度が制限されているのでそこを修正した上で考える」
- オネージャーの発射熱：「Cool what fits」（入るだけ変換装置を積み、残りは蓄熱）。

## 全艦共通の機関母線（`engineTransmission`、`engineSceneSupply`）

- 機関は、自分の電源ドメインのすべての反応炉から自動の送電路を受け取る。既に作成済みの経路で届く反応炉には、経路を追加しない。
  - 機関専用の炉を持つ艦（アークワイテンス級など）は、これまで主反応炉から給電されていなかった。
- 利用者が機関に設定した `feedCapacityW` は、経路ごとではなく、その機関に入る経路の合計にかかる。
  - 残りを電源の出力の比で各経路に分ける。
- 機関の要求（`buildPropulsionRequests`）は、届く電源全体ではなく、機関の大きさで分けた取り分（`ratedInputW`）にする。
  - 取り分を使えない機関がある場合、その分を同じドメインの他の機関に配る（water filling）。例：止まっている機関、軸や給電路の容量が足りない機関。
  - 旧形式で、複数のノズルが同じ機関を指す要求には配らない。
- 駆動軸は機関の取り分の大きさで作る（`engineShareInputW`）。
  - 機関本体より太い管が要るときは、本体に入る最も太いポート（半径の 0.9 倍）を取る。管の太さと容量は既存の細径経路の探索で決まる。
  - 以前は、この場合は「経路なし」で容量 0 だった。

## 持続巡航に合わせた冷却（`shipThermalCruiseModel`、`shipSustainedCruise`、`refitShipThermal`）

- 最高速度：ゲームが表示し、実際に飛ぶ値（戦闘用性能表の `healthyMotionPlan`。艦内設備と冷却に先に給電し、残りが機関に行く）。
- 巡航：同じ性能表で、シールドを保持し兵装は休止とし、機関のスロットルを x にしたときの解。
  - 機関には炉の残りしか行かないので、巡航の負荷が炉の出力を超えることはない。
- 巡航の発熱は次の合計：
  - 炉の廃熱 × 使った電力
  - 機関の廃熱（曲線 B）
  - シールドと艦内設備の廃熱
  - 給電路の損失
  - 変換装置の入力分（変換した熱に比例するので、反復して収束させる）
- 変換装置の容量：最高速度の `CRUISE_SPEED_TARGET.target`（0.7）を保てる x での発熱に、超兵器の分を足したもの。
  - 超兵器の分は、発射時の発熱と再充電中の損失のうち大きい方。
  - 作例が既に置いている変換装置がこの容量を超える場合は、全部同じ倍率で縮める。配電ハブは除く。
- 超兵器の発射熱が入りきらない場合、巡航の分が満たされていれば組み立てを止めず、不足分を `fireShortfallW` に記録する。
- 戦闘はこの容量を超える。超えた分は蓄熱に入り、満ちれば自動の調速器が出力を絞る（設計画面の「戦闘負荷で…不足」の警告は、この方針どおりの表示）。
