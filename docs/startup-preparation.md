# 起動時の作例準備

タイトル画面を開いた時点から、共有3D部材、戦闘定数、マップ・星系データを取得する。カタログで指定した作例図面も、低優先度で2件ずつダウンロードする。取得済みデータはSHA-256を検証して再利用する。

別のWorkerが、通常表示と試験飛行の両方について、3Dモデル、設計数値、完全な戦闘プロファイル、機関・区画の計算結果を準備し、IndexedDBへまとめて保存する。ユーザーが設計操作や戦闘を始めた場合は準備用Workerを中断し、操作を優先する。入力が落ち着いた後に未完了の作例から再開する。

準備が完了した作例は、新しいWorkerやページ再読み込み後にも保存済みデータを復元する。通常のキャッシュ整理によって、同じ版の別の作例を準備したために先に準備した作例が消えることはない。ブラウザーが保存を許可しない場合や実際の保存容量を超えた場合は、保存成功として数えない。

計算と描画に使うソースは、画面とWorkerで同じ検証済みバイト列を使う。版が変わった場合は古い計算結果を混ぜない。公開する圧縮図面は、実際の機関寸法、質量、給電、排熱、接地と射線を検証した図面に限定する。読み込む図面のコード版やチェックサムが一致しない場合は通常の作例構築へ戻る。

## 検証

- `tests/startup-preload.cjs`：処理の同時実行数、操作時の中断、失敗時の継続。
- `tests/prepared-ship-cache.cjs`：別Workerでの完全なモデル・数値の復元と、作例キャッシュの保持。
- `scripts/browser-startup-preload.cjs`：実ブラウザーでの図面ダウンロード、CacheStorage、Worker、IndexedDB、再読み込み後の復元。
- `scripts/browser-prepared-ship-cache.cjs`：復元した数値・戦闘プロファイルと全メッシュのバイト一致。

ブラウザー試験の小型図面は、保存と復元の経路を調べるためのもの。全28艦の描画性能や、アプリ画面全体のWebGL描画の試験を代替するものではない。
