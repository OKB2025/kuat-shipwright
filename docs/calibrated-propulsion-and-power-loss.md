# 質量に応じた推進校正と電力喪失時の航行不能

この記録はPR #76時点の校正と検証を示す。現在のスロットル、固定給電順、蓄熱表示、90%速度によるハイパースペース進入と点防御切替は[操艦レバー・戦闘給電・ハイパースペース進入](flight-controls-power-and-hyperspace.md)を参照。以下の過去の画面・優先モードの記録は履歴として保持する。

全エンジンの電力から推力への換算を共通化し、TIE/lnの4,100G、ヴェネター級の3,000Gを基準に校正する。インペリアル級についても同じ式と実際の給電・動力伝達路から結果を確認する。艦名による実行時の加速上限や、外装／内蔵機関ごとの別換算は加えない。

## 電力と加速

艦全体の実質量を`M`、受電電力を`P`、単位推力に必要な入力電力を`K(M)`とする。

```
K(M) = Ksmall × (M / Msmall)^α
加速G = P / (M × K(M) × 9.80665)
```

`α`は、実際の小型機・大型艦の基準値から求める正の指数。小型ほど1kgを1G加速させる必要電力が小さくなる。基準点は固定し、運転中の受電量やスロットルから目標Gへ合わせ直さない。装備・弾薬の搭載で実質量が変われば、同じ共通式を使って実推力と加速を計算する。

機関入力は接続した有限の電源予算を共有し、手入力の旧定格を上限にしない。実受電の95%を有効出力、5%を機関廃熱とする分配を維持し、推力の換算と熱を別々の数値で偽装しない。スロットルを下げれば実受電・推力・噴射・発熱が同じ経路で下がる。

TIE/lnの新規作例では、ユーザー指示に従って実リアクターを小さくし、変更後の容積・出力・質量で4,100Gへ合わせる。入力を旧定格で絞って見かけだけ合わせない。太陽光パネルの左右各1部品という構成は維持する。保存済みのユーザー図面へ作例の炉の寸法変更を適用しない。

旧工場生成の入力定格から作った給電上限は、由来と元の値を確認できるものだけを移行する。ユーザーが変更した有限の給電容量、実ノズルや機械伝達路の容量・損傷・閉塞は保持する。動力伝達路は既存の実形状・干渉判定を通るものだけを有効にする。

骨組み重量と強度、縦強度による加速・推進入力制限、慣性制御、排熱、燃料、機器損傷の制約を継承する。健全時の設計値と、必須設備電力・給電損失・物理経路に制限された実給電時の値は区別して記録する。

## 抵抗と速度

既存の1MGLT＝20m/sを継承し、TIE/ln100MGLT、ヴェネター50MGLTを健全時の抵抗校正基準とする。実際の加速と基準速度から、全艦共通の抵抗係数を求める。

```
減速係数 k(M) = ksmall × (M / Msmall)^δ
抵抗力 = M × k(M) × 速度
```

`δ`も2つの基準点から求める。今回の値は約0.02793で、抵抗力は質量の約1.02793乗で増え、概ね質量に比例する。

同じ実質量なら抵抗係数は同じで、リアクターの出力を増やしても抵抗を増やして旧速度へ戻さない。実推力が増えれば釣り合う速度も増える。艦級の公表速度は出典情報として残し、実際の最高速度は共通式から計算する。

運転中のスロットル・故障・弾薬重量で校正基準を作り直さず、実推力と抵抗の差を積分する。最高速度の固定値で速度ベクトルを切り詰めない。全出力時の釣り合い付近で25%へ下げると減速し、静止からは同じ25%出力で低い釣り合い速度へ加速する。

## 電力喪失

負荷配分前の実稼働電源を確認する。熱停止・既知の燃料枯渇・電源や給電系の停止で電力を失うと、既存の`電源喪失`による航行不能へ移す。スロットル0、兵装優先、超兵器への電力予約だけでは電源喪失としない。生きた太陽光パネルなどの代替電源も確認する。

失電時は操艦・旋回・射撃・ジャンプを止め、既存の航行不能時の重力・落下と抵抗を使う。速度を瞬時に0へ書き換えない。停電した艦は既存の牽引・回収・任務群ジャンプ判定へ接続する。

一時的な電源喪失を所有する印を付け、電源復旧後はその理由だけを解除する。艦橋喪失、乗員不足、拿捕などの別理由を上書き・解除しない。旧攻撃・ジャンプ命令は自動再開しない。熱停止からの乗員による既存の再起動作業と熱損傷の出力上限も継承する。

## 保存と検証

推力換算と抵抗の版を更新し、保存された古い正の換算係数も再生成する。Core・Worker・艦隊・艦載機・試験飛行とUIは同じ質量・換算結果を使う。確定した質量がまだ届いていないUIは計算中と表示し、独自の物理値を推定しない。

検証結果には、基準3艦の実図面・質量・出力・受電・推力・加速・熱・速度、25%／0%出力、失電・復旧・落下、保存移行と実ブラウザ操作を記録する。未検証環境や既存失敗は成功と混同しない。

## 実図面の結果

最新Coreから各作例を1回ずつ新規生成し、冷間時の全出力と、静止から120秒の航行を測定した。速度を初期値に与えず、通常の給電・燃料消費・発熱・排熱を処理した。これは120秒の作動確認であり、熱平衡や無期限の航行を保証する試験ではない。

|作例|実質量|設計上の加速|冷間時の実給電加速|推力と抵抗が釣り合う速度|120秒後の速度|
|---|---:|---:|---:|---:|---:|
|TIE/ln|8.0814t|4,100.016G|3,999.104G|100.000MGLT|1,981.921m/s|
|ヴェネター級|11,800,135.064t|3,000.000G|2,972.473G|50.000MGLT|999.084m/s|
|インペリアルI級|49,713,858.077t|2,163.756G|2,163.756G|34.963MGLT|698.788m/s|

TIE/lnの炉は直径1.6mから0.9916610784mへ変更した。有効容積0.1240927414m³から得られる実炉出力は約6.49874×10¹⁷W。左右の太陽光パネルを含む発電可能電力は約7.10446×10¹⁷W、冷間時の機関受電は約6.33869×10¹⁷Wとなった。左右各1部品のパネル形状・出力を保持し、部品数は25のまま。新規作例の物理改訂を2へ更新し、作例の古い性能キャッシュを再生成する。

インペリアル級は約2,300Gの目安に対して5.924%低い。中央の実伝達路は周囲の副機関に制限され、要求容量の約83.908%となる。外側2本と補助軸は全容量を通す。経路は実際の機関・ノズル内に接続し、既存の船内・端面・干渉判定を通す。容量や密度を増やして差を隠していない。公表値60MGLTは出典情報として残し、実速度へ固定しない。

自動軸の容量計算で最大運転倍率を重ねて掛けていた箇所も修正した。その結果、派生する軸の断面・長さ・材料量が変わる場合がある。[公開試験用図面での質量比較](benchmarks/calibrated-propulsion-mass-attribution.json)では、同じ入力図面・炉・骨組み・装甲のまま、軸材料と置換する船体材料の差から総質量が約1,978.343t（0.00155%）減った。密度や骨組みの補正によるものではない。

自動給電リンクは保存時に自動生成の由来だけを記録し、容量を実電源から再計算する。ユーザーが指定した有限容量と0容量は保存する。電源の増強・停止・復帰で古い名目加速上限を再利用せず、明示された構造・慣性・経路の制限は保持する。
